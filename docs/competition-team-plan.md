# 四人按实际功能模块分工

移动与网络应用开发类赛项，剩余 12 天。成员 1–4 各自负责一个完整模块的页面、接口、必要数据结构、测试和演示。新增能力均为建议开发内容。

## 成员 1：票根采集与智能录入

目标：快速、准确地把纸质票根或截图变成可检索记录。

已有基础：批量图片队列、OCR、字段校对、地点规范化、图片去重和缩略图。

具体任务：
- 增加图片裁切、旋转与预览；手机可拍照或选相册。
- 改进日期、类型、地点提取，展示抽取依据和待校对状态，有歧义时让用户确认。
- 完善批量编辑、进度和失败重试，已保存项不重复上传。
- 重复提示支持查看已有票根，用户明确选择后才重复收藏。
- 用实际授权脱敏票根测字段准确率、修正次数和录入耗时。

主要文件：ocr_service.py、media_service.py、templates/upload.html、static/js/upload.js、上传专属样式与测试。

交付：拍照/选图 → 裁切旋转 → 识别 → 校对 → 保存。

验收：处理图片、OCR 输入与最终保存图片一致；原始素材保留策略明确；批量重试不重复保存；手机可完成流程。

节点：D4 主流程可用，D6 批量体验和评测完成。

## 成员 2：精准记忆检索与有据问答

目标：准确回答指定时间、地点、类型的经历，并能追溯来源。

已有基础：图文混合检索、带票根引用的问答和本地降级。

具体任务：
- 解析并确认时间、城市、类型条件，先过滤再检索；用户可以修改筛选条件。
- 校准相关性阈值，无相关记录时返回空，避免无关票根填充答案。
- 全量聚合城市、年度等统计问题，避免仅根据少量召回结果作统计结论。
- 展示来源、匹配理由、覆盖范围与降级状态，完善超时和失败反馈。
- 为成员 4 提供已选票根的有据讲述草稿服务；展览可先用用户备注实现。
- 标注查询并比较改进前后的 Recall@5、条件命中和无结果判断，调参集与测试集分开。

主要文件：semantic_service.py、templates/memory.html、static/js/memory.js、static/css/memory.css、相关查询函数与测试。

交付：可确认筛选条件、可核对来源的记忆问答页面与真实评测结果。

验收：条件与结果一致；无关问题可返回空；统计覆盖全部相关记录；引用属于当前用户；第三方服务失败不阻塞页面。

节点：D4 精准查询可用，D6 引用、降级和评测完成。

## 成员 3：足迹地图、时间轴与年度数据联动

目标：从城市或时间段直接回顾对应票根，形成连贯的时空浏览体验。

已有基础：地图、省市统计、时间轴、年度统计与部分筛选。

具体任务：
- 点击省市联动对应票根列表，地图选择与列表范围一致。
- 城市、年份、月份条件跨地图与时间轴保留，明确显示筛选范围。
- 年度图表下钻到对应票根，例如点击某月查看该月收藏；区分票据日期与入库日期。
- 增加选择票根创建展览入口，把有序票根 ID 交给成员 4。
- 完善手机点按、缩放、切换和加载、空结果、失败状态。
- 仅在票根明确给出起点、终点和日期时显示行程连线，未知地点不推断成真实路线。

主要文件：templates/map.html、timeline.html、stats.html；static/js/map.js、timeline.js、stats.js；模块专属样式与查询测试。

交付：按地点/时间筛选 → 浏览 → 跳转详情 → 选择票根进入展览。

验收：相同条件对应同一批记录；跨页面按约定保留条件；移动端不依赖悬停；没有来源的路线不展示成真实行程。

节点：D4 地图时间联动，D6 年度统计和展览入口完成。

## 成员 4：主题回忆展览与海报输出

目标：把选中票根变成可保存、编辑、播放、导出的个人记忆作品。

已有基础：可复用票根详情、图片、备注、日期和地点；展览与海报待开发。

具体任务：
- 选择 3–8 张票根、调整顺序、设置主题，用一套模板呈现。
- 实现创建、保存、重新打开、编辑和删除展览，后端校验用户归属。
- 章节播放同步展示原票面、日期、地点与讲述，支持按钮和键盘切换。
- 默认使用票根字段和用户备注；可接入成员 2 的讲述草稿，保留人工编辑和无网替代。
- 章节能跳回原始票根，处理票根删除、图片缺失等状态。
- 导出主题海报，提供预览和脱敏。原图可能含姓名、号码和二维码，无法可靠遮挡时默认不纳入导出。

建议新增：story_routes.py、story_service.py、story_database.py、templates/story.html、static/js/story.js、static/css/story.css 和模块测试。

交付：选择 → 创建 → 编辑保存 → 播放 → 查看来源 → 导出。

验收：刷新后可继续编辑；顺序和修改保留；不能访问他人展览；不补写无记录的情绪、同行者和经历；导出与预览一致并落实脱敏。

节点：D4 创建保存可用，D7 播放、来源和海报完成。

## 模块连接与代码归属

1. 成员 1 保持现有票根 ID 和字段，新证据字段兼容旧记录。其他人使用既有收藏开发，不等待录入优化完成。
2. 成员 2/3 向成员 4 传递有序 ticket_ids；成员 4 在服务端重新检查归属、存在性和数量。展览可以先独立选票根。
3. 成员 2 的讲述服务输入已选票根，返回草稿和引用。服务尚未完成时，成员 4 用用户原始备注继续开发。
4. D1 共同确定筛选参数、日期格式、省市标准值和成功、空结果、失败样例。
5. 各人维护模块专属页面、JS、CSS 与测试。新模块用独立 Blueprint 和迁移函数接入。
6. app.py、database.py 的小改动由成员 2 汇总；首页与 base.html 导航改动由成员 3 汇总。汇总只用于减少冲突，各人仍负责完整功能。
7. 每人使用独立副本及 feature/capture、feature/memory、feature/spacetime、feature/story 分支。先确认当前未提交改动作者并建立共同基线。

## 12 天共同节奏

- D1：认领模块，固定字段与连接点，各自列主流程和验收条件。
- D2–D4：各模块交付可操作的第一版，D4 共同演示。
- D5–D7：完成连接，D7 跑通采集 → 检索/时空回顾 → 选择 → 展览 → 导出。
- D8–D9：各自测试和交换验收，记录真实数据与失败案例；跨模块测试使用同一版本。
- D10：新环境启动、断网和第三方失败检查；冻结新增需求，修复阻塞问题。
- D11：每人提供自己的说明、实测记录、截图、30–45 秒录屏和原创贡献；分别承担录入、检索、时空、展览四段材料。
- D12：按最终包共同演练，指定一人提交、另一人复核。提交和材料整合作为附加事务。

每个模块完成必须满足功能可操作、相关回归通过、另一人验收、自己的说明与演示可用。每天同步 15 分钟并预留联调时间。

进度落后时压缩多模板、装饰动效和行程连线，保留准确检索、基本联动、可靠保存、来源和用户隔离。
